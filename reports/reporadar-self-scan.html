Where the fine-scale rescore cut

The 0–3 gate put 27 of 50 papers into a single score-2 bucket — near-binary, exactly the failure the fine-scale pass exists to fix. Re-read on a 0–9 scale with the probability taken from the token distribution, those 13 candidates spread across almost the entire interval. The threshold is derived, not tuned: net@2 pays 3p − 2 per paper shown, so showing pays exactly above p = 2/3.

What the run says about the run

HyDE carried 14 of the 15 papers

Every Top Pick but one, and all eight Maybe Relevant papers, matched hyde — found by dense retrieval against the local arXiv index, not by any of the six keyword queries. The single keyword-sourced paper came from all:mcp, the one query whose term is a genuine domain concept rather than repository vocabulary.

This is an in-situ replication of the README's headline claim, on a repository that was not in the benchmark.

The generated keyword queries are weak, and it shows

TF-IDF over this repo produced pytest, repo, papers, digest and run reporadar as query terms. Those are tooling and self-reference vocabulary, not domain concepts, and (all:pytest) AND (cat:cs.IR OR …) is close to a null query for literature about paper discovery. 220 papers came back and exactly one reached the digest.

Worth considering as a real finding about the profiler: a repository whose README is largely about its own machinery feeds its own vocabulary back into the query builder. Adding domain seed queries under queries.seed would be the cheap test.

The coarse gate really is near-binary

Of 50 papers triaged, the 0–3 gate assigned: 3 papers a 0, 18 a 1, 27 a 2, and 2 a 3. More than half of everything it saw landed in one bucket. The fine-scale pass then spread 13 of those across P = 0.047 to 0.852 and rejected 8. That is the mechanism the README describes, behaving as described, on fresh data.

Paper #1 is about the thing paper #1 was found by

“Topic Is Not Agenda” argues that cosine similarity between text embeddings does not reliably track conceptual relatedness, and it was surfaced by a pipeline that ranks on cosine similarity between text embeddings (ranking.w_embedding: 1.5) over a dense index. It is the highest-confidence recommendation in the run and it is a direct challenge to a weight the measured config depends on. That combination makes it the one worth reading first.

What this report does not establish. The +5.72 mean net@2, 0.892 precision and paired-delta figures in the README come from the 25-repository benchmark. They are not measurements of this run. Nothing here was judged against ground truth — there is no labelled gold set for this repository, so “7 actionable papers” is the gate's claim about itself, not a verified count.

Two further limits: the gate scored this repo's papers with knowledge of what RepoRadar is, which is exactly the intended behaviour but also means the recommendations cluster tightly around paper-discovery systems; and recency: 1.00 on several entries reflects sort_by: relevance over an all-time window, so freshness is not a signal that separated anything here.

Reproducing this

The configuration is committed at .reporadar.yml. Two deviations from a stock rr init --measured, both recorded in the file: arxiv.categories was set to this repo's actual fields, and hyde.index_dir points at the index the eval harness had already synced (evals/.work/hyde_index, 36 shards, 1991–2026) rather than re-downloading 417 MB into the default cache. Keys were loaded from evals/.env into the run's environment; the config reads them through ${ANTHROPIC_API_KEY} and ${OPENAI_API_KEY}.
